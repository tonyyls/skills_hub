## 目标

- 为“未分类”的技能批量识别分类并打标签，直接在本地执行，不依赖 Vercel 定时。

## 前置条件

- 已在 `.env` 配置 `GLM_API_KEY` 并重启后端。
- 管理员登录可用（用于调用受保护接口）。

## 实施步骤

1) 新增后端批处理接口（受管理员鉴权）
- `POST /api/admin/ai/auto-classify`
- 入参：`limit`（默认 50，最大 200）、`minConfidence`（默认 0.6）
- 流程：
  - 查询 `skills` 中 `category_id` 为空的前 `limit` 条
  - 拼接 `title + "\n" + description` 作为识别输入
  - 调用已封装的 `AiService.classifyCategory(text, categories)`
  - 当 `confidence ≥ minConfidence` 时：
    - 写回 `category_id = result.categoryId`
    - 合并 `tags`（去重，最多追加 3 个）
  - 统计并返回 `{ total, updated, lowConfidence, errors }`
- 日志：记录每次处理的条数与失败原因（不输出密钥）。

2) 可选预览接口（不写库）
- `GET /api/admin/ai/auto-classify/preview?limit=50`
- 返回待处理技能的分类与标签建议，辅助抽样复核。

## 本地执行流程

- 启动后端：`npm run server:dev`
- 管理员登录获取 `token`：
```bash
curl -s -X POST http://localhost:3010/api/admin/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"tonyadmin"}'
```
- 执行批量识别与打标：
```bash
curl -s -X POST http://localhost:3010/api/admin/ai/auto-classify \
  -H "Authorization: Bearer <你的token>" \
  -H 'Content-Type: application/json' \
  -d '{"limit": 50, "minConfidence": 0.6}'
```
- 查看返回统计与日志，如效果良好，重复调用至处理完毕。

## 参数建议

- `limit`：50–100（控制单次耗时与速率）
- `minConfidence`：0.6–0.7（提升可靠性，低置信度保留供人工复核）

## 风险与控制

- 误分类：通过阈值控制 + 预览抽样；低置信度不自动写库
- 并发：建议单操作者触发，避免重复处理同一条记录
- 审计：返回与日志包含处理数、低置信度与错误计数

## 成功标准

- 返回统计的 `updated` 数量与示例抽样准确率达到预期（如 ≥ 80%）
- 低置信度样本数量可接受；后续由人工处理
