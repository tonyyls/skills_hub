## 目标与度量
- 基础流量：PV、UV、会话、页面停留时长、来源/UTM。
- 产品行为：自定义事件（搜索、收藏、下载、安装指令复制、Tab切换）。
- 性能指标：Core Web Vitals（LCP/FID/CLS）与首屏加载时间。
- 隐私合规：不采集 PII，遵守 DNT/Consent，支持用户退订。

## 方案选型
### 方案 A：Vercel Analytics（零配置，隐私友好）
- 文档：https://vercel.com/docs/analytics
- 优点：接入简单、Cookieless、原生与 Vercel 集成；可看基本流量与 Web Vitals。
- 缺点：事件维度较弱，产品行为需另行埋点。

### 方案 B：Plausible（开源、Cookieless）
- 文档：https://plausible.io/docs
- 优点：隐私友好、支持自定义事件与目标、轻量前端脚本。
- 缺点：需托管或付费 SaaS；事件分析能力中等。

### 方案 C：Umami（开源自托管）
- 文档：https://umami.is/docs
- 优点：自托管、支持事件与仪表盘；可自定义域名与脚本。
- 缺点：需维护服务与数据库。

### 方案 D：Google Analytics 4（GA4）
- 文档：https://developers.google.com/analytics/devguides/collection/ga4
- 优点：生态丰富，报告全面；支持事件与转化。
- 缺点：隐私合规复杂；脚本体量相对较大。

### 方案 E：PostHog（产品分析）
- 文档：https://posthog.com/docs
- 优点：事件分析、漏斗、留存、Session Replay；可自托管。
- 缺点：学习与维护成本较高。

### 方案 F：自建 Supabase 事件埋点（后端直写）
- 优点：完全掌控数据结构与合规；与现有后端融合；无第三方脚本。
- 缺点：需设计表与聚合逻辑、仪表盘实现。

## 推荐组合
- 基础流量与性能：优先用 Vercel Analytics 或 Plausible（二选一）。
- 产品行为与转化：自建 Supabase 事件埋点（与当前栈融合），用于关键事件与看板。

## 技术实现
### 一、基础流量脚本（Plausible 示范）
- 在 `index.html` 注入脚本（使用环境变量 `VITE_PLAUSIBLE_DOMAIN`）：
```html
<!-- index.html -->
<script defer data-domain="%VITE_PLAUSIBLE_DOMAIN%" src="https://plausible.io/js/script.js"></script>
```
- 路由 PV 上报（Vue Router afterEach）：
```ts
/**
 * 上报页面浏览（Plausible）。
 * @param path 当前路径
 */
function trackPageview(path: string): void {
  // @ts-ignore
  if (window.plausible) window.plausible('pageview', { props: { path } })
}
router.afterEach((to) => {
  trackPageview(to.fullPath)
})
```

### 二、产品事件埋点（Supabase）
- 事件表设计（PostgreSQL / Supabase）：
```sql
CREATE TABLE IF NOT EXISTS analytics_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NULL,
  session_id TEXT NULL,
  event_name VARCHAR(64) NOT NULL,
  event_time TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  path TEXT NOT NULL,
  referrer TEXT NULL,
  utm JSONB NULL,
  props JSONB NULL
);
CREATE INDEX idx_ae_event_time ON analytics_events(event_time DESC);
CREATE INDEX idx_ae_event_name ON analytics_events(event_name);
```
- 埋点助手（前端直写后端或直接 Supabase）：
```ts
/**
 * 上报自定义事件（Supabase）。
 * @param name 事件名，如 'search','favorite','download','install_copy','tab_switch'
 * @param props 附加属性
 */
export async function trackEvent(name: string, props: Record<string, any> = {}): Promise<void> {
  const body = {
    event_name: name,
    path: window.location.pathname,
    referrer: document.referrer || null,
    utm: extractUtm(),
    props
  }
  await fetch('/api/analytics/events', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Accept': 'application/json' },
    body: JSON.stringify(body)
  })
}
function extractUtm(): Record<string, string> | null {
  const usp = new URLSearchParams(window.location.search)
  const keys = ['utm_source','utm_medium','utm_campaign','utm_term','utm_content']
  const kv: Record<string, string> = {}
  keys.forEach(k => { const v = usp.get(k); if (v) kv[k] = v })
  return Object.keys(kv).length ? kv : null
}
```
- 页面/交互埋点示例：
```ts
// 首页 Tab 切换
trackEvent('tab_switch', { tab: activeFilter.value })
// 搜索
trackEvent('search', { q: searchQuery.value })
// 收藏
trackEvent('favorite', { skill_id: skill.id })
// 复制安装命令
trackEvent('install_copy', { skill_id: skill.id })
```

### 三、性能指标（Web Vitals）
- 文档：https://web.dev/vitals/
- 前端上报：
```ts
import { onCLS, onFID, onLCP } from 'web-vitals'
function sendMetric(name: string, value: number) {
  trackEvent('web_vital', { name, value })
}
onCLS((m) => sendMetric('CLS', m.value))
onFID((m) => sendMetric('FID', m.value))
onLCP((m) => sendMetric('LCP', m.value))
```

## 仪表盘与查询
- Plausible / Vercel：使用平台自带仪表盘。
- Supabase：SQL/视图聚合 + 前端简单看板。
```sql
-- 最近7天事件量按事件名聚合
SELECT event_name, COUNT(*) AS cnt
FROM analytics_events
WHERE event_time >= NOW() - INTERVAL '7 days'
GROUP BY event_name
ORDER BY cnt DESC;
```

## 隐私与合规
- 不采集邮箱/手机号等 PII；IP 哈希或不记录。
- 尊重 DNT（Do Not Track），可在客户端判定并不上报。
- 提供隐私政策与 Opt-out 入口；Cookie 同意管理（若采用 GA）。

## 环境与配置
- Vercel 环境变量：`VITE_PLAUSIBLE_DOMAIN`、后端事件 API 的鉴权密钥（如需要）。
- 分环境开关：预览与开发可只启用 Supabase 事件，生产开启外部分析。

## 实施步骤
1. 选型：基础（Vercel Analytics 或 Plausible）+ 事件（Supabase）。
2. 注入基础脚本并添加 Router 上报。
3. 落地前端埋点助手，在关键交互调用 `trackEvent()`。
4. 后端接收 `/api/analytics/events` 写库；建立查询与简单看板。
5. 验证准确性与性能开销，完善隐私合规与开关。
