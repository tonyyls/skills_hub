## 目标
- 在分类数据接口中增加英文名称字段，前端根据当前语言显示对应的分类名称。
- 兼容旧数据与现有页面，中文/英文双语均正常。

## 后端改动
- 数据库（Supabase Postgres）
  - 为 `categories` 表增加英文名称字段 `name_en`（可空）。
  - SQL：
  ```sql
  -- 新增字段
  ALTER TABLE public.categories ADD COLUMN IF NOT EXISTS name_en text;
  -- 可选：创建索引以便后台查询
  CREATE INDEX IF NOT EXISTS idx_categories_name_en ON public.categories (name_en);
  ```
- 接口返回
  - 公共接口 `GET /api/categories`：返回 `id, name, name_en`，并支持语言选择：
    - 读取 `Accept-Language`（或 `?lang=en|zh-CN`）决定客户端显示用哪个字段。
    - 当 `name_en` 为空时，英文环境回退到 `name`。
  - 管理端接口 `GET/POST/PUT /api/admin/categories`：支持读写 `name_en` 字段。
- 开发态（devStore）
  - `api/utils/devStore.ts` 读写 `categories.dev.json` 时保留并透传 `name_en` 字段。
  - 示例数据（仅演示结构）：
  ```json
  [
    { "id": "frontend", "name": "前端开发", "name_en": "Frontend" },
    { "id": "backend", "name": "后端开发", "name_en": "Backend" }
  ]
  ```

## 前端改动
- 类型与存储
  - 在 `Category` 类型加入 `name_en?: string`。
  - `src/stores/skills.ts`：
    - 拉取 `/api/categories` 后，构建 `categoryMap` 时根据当前 `i18n` 语言优先使用 `name_en`，否则回退 `name`。
    - 当语言切换时，重建 `categoryMap`（或在显示层动态选择）。
- 显示规则
  - 列表页（`/skills`）、首页、收藏页等，调用 `getCategoryName(category_id)` 时按语言返回：
    - `en`：`name_en || name`
    - `zh-CN`：`name`
- 可选优化
  - 前端请求时附带 `Accept-Language` 头或 `?lang`，便于服务端根据语言做排序或过滤。

## 接口示例
- 请求：
```http
GET /api/categories
Accept-Language: en
```
- 响应：
```json
{
  "items": [
    { "id": "frontend", "name": "前端开发", "name_en": "Frontend" },
    { "id": "backend", "name": "后端开发", "name_en": "Backend" }
  ],
  "etag": "\"abc123\""
}
```

## 兼容与回退
- 当 `name_en` 缺失：英文环境显示中文 `name`，保证不空白。
- 管理端允许逐步补充英文名称；批量录入时不强制要求。

## 安全与规范
- 不改变鉴权逻辑；仅增加字段。
- 管理端保存时，对 `name`/`name_en` 做长度与字符集校验，避免脚本注入。

## 验证与测试
- 后端：
  - `GET /api/categories` 在 `Accept-Language=en|zh-CN` 下返回包含 `name_en`；
  - 管理端新增/编辑分类时 `name_en` 正常读写。
- 前端：
  - 切换语言后，分类名称展示正确：英文优先 `name_en`，中文展示 `name`。
  - 首页与技能页筛选标签中的分类计数与名称对齐。
